# Go hot-path audit before v2 design

This is a **pre-v2 implementation audit, not a Go API design**. It records the current request, routing, transport, and response paths to establish implementation constraints before designing a clean Go v2 API. The existing Rust-oriented feature specifications are not treated as a Go design.

The audit examined the working tree based on commit [`1ceaac8172bda26e8b8d701ac356982d33729b27`](https://github.com/scylladb/gocql/commit/1ceaac8172bda26e8b8d701ac356982d33729b27). Production-code references below are pinned to that commit. The source inspection was read-only; no driver code was edited and no tests were run. Existing working-tree changes were left untouched. This document was subsequently saved as the sole audit artifact.

The implementation has useful transport and response ownership boundaries, but a typed path must bypass both `Marshal` and `Scan`: both sit after values have crossed dynamic `any` boundaries, and both retain per-value work that generics alone would not remove.

## Request values and final frame assembly

| Area | Current path and relevant boundary |
|---|---|
| Query arguments | [`Session.Query`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/session.go#L632) stores the supplied `[]any` directly in `Query.values`. `Query.Bind` replaces that slice directly. `Session.Bind` stores a callback returning `[]any`. |
| Query execution | [`Conn.executeQueryWithMetrics`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/conn.go#L2606) prepares eligible DML, invokes the binding callback, checks argument count, obtains pooled `[]queryValues`, and calls `marshalQueryValue` once per argument. |
| Value serialization | [`marshalQueryValue`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/conn.go#L2527) unwraps `NamedValue`, handles `UnsetValue`, then calls `Marshal(TypeInfo, any)`. Each `queryValues` holds a separately encoded `[]byte`, a name, and an unset flag. |
| QUERY | The nonprepared branch creates `writeQueryFrame` with no serialized `qry.values`. The frame machinery supports values, but this execution branch does not populate them. See [`writeQueryFrame`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/frame.go#L1658). |
| EXECUTE | [`writeExecuteFrame`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/frame.go#L1706) writes prepared ID, optional result metadata ID, and query parameters. [`writeQueryParams`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/frame.go#L1543) writes each encoded value using `writeBytes`. |
| BATCH | [`Conn.executeBatch`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/conn.go#L2959) allocates `[]batchStatment`; entries with arguments/binding are prepared and serialized through the same `marshalQueryValue` path. Entries without arguments/binding use statement text. [`writeBatchFrame`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/frame.go#L1768) appends each entry's values. |
| Final frame assembly | [`framer.writeBytes`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/frame.go#L2214) appends the length and copies payload bytes into contiguous `framer.buf`. Consequently even `DirectMarshal` and blob inputs that originally borrow user storage incur this copy. |
| Socket ownership | [`Conn.execInternal`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/conn.go#L2204) acquires a stream/write framer, builds the frame, applies v5 layout if needed, calls `writeContext`, and only then releases the write framer. The response framer is separately acquired and transferred to the caller. |

Serialization details that matter:

- [`Marshal` / `marshal`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/marshal.go#L173) perform a reflection-based pointer check, custom marshaler dispatch, and a CQL-type switch. Scalar packages perform another Go type switch; named scalar types fall back to reflection.
- Scalar encoders return standalone byte slices. For example, [`cqlint.EncInt32`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/serialization/cqlint/marshal_utils.go#L43) constructs four bytes, while [`text.encString`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/serialization/text/marshal_utils.go#L57) converts a string to `[]byte`. Text/blob byte-slice input can be returned directly before frame assembly copies it.
- [`marshalList`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/marshal.go#L744) reflects over elements, recursively calls `Marshal`, and copies each encoded element into `bytes.Buffer`; its map-as-set path additionally constructs `[]any`. Map, tuple, and UDT encoding have corresponding recursive reflection/interface and intermediate-buffer paths. UDT struct field maps are rebuilt during each call.
- There are existing specialized float vector paths in [`marshalVector`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/marshal.go#L887), but these still produce a separate encoded value buffer. They demonstrate that removing reflection and removing payload copies are separate changes.
- `[]queryValues` is pooled, but the encoded payloads are not pooled by that mechanism. [`putQueryValues`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/frame.go#L1464) clears references after the entire round trip, although frame construction consumed them before the write.

## Transport copies and encoding

| Transport | Existing copy/encoding behavior |
|---|---|
| v4, no compression | Values are copied into one CQL frame buffer, then passed to the writer. Buffer growth can introduce additional copies. |
| v4, compression | [`framer.finish`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/frame.go#L703) passes the body to `Compressor.Encode`, then copies the compressed output back behind the header. Built-in Snappy and LZ4 encode into newly allocated output. |
| v5, no compression | [`prepareModernLayout`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/frame.go#L2275) builds segments into a second reusable `wireBuf` and swaps buffers. [`segment.AppendUncompressed`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/internal/segment/segment.go#L313) copies each raw-frame chunk between its segment header and CRC. Pool reuse removes repeated allocation, not this copy. |
| v5, compression | [`segment.AppendCompressed`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/internal/segment/segment.go#L345) appends compression output directly into the destination wire buffer. If compression does not shrink the segment, the segment writer copies the original payload into the reserved output instead. [LZ4's append methods](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/lz4/lz4.go#L116) can reuse capacity. |
| Write coalescing | [`writeCoalescer.flush`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/conn.go#L2133) passes `net.Buffers` to `WriteTo`. It copies slice descriptors because `WriteTo` mutates them; it does not first flatten their payloads. The present buffers are whole frames, not individual values. |
| TLS | [`WrapTLS`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/dial.go#L105) wraps the connection with `tls.Client` and sets `DisableCoalesce` because the wrapper cannot use writev. This path writes the assembled frame through TLS. Any zero-copy claim must distinguish driver assembly from TLS record encryption and socket copying. |
| v4 reads | [`framer.readFrame`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/frame.go#L399) reads the body into a pooled read buffer. Decompression produces separate decoded output for the built-ins. Reads go through a `bufio.Reader`, so buffering may add a copy depending on read size. |
| v5 reads | [`segment.ReadPayload`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/internal/segment/segment.go#L177) returns a view into connection-local reusable scratch. Self-contained frames are copied into independent read framers. Large split frames are copied from segment scratch into a once-sized reassembly buffer by [`recvSplitFrame`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/conn.go#L1581), then [`adoptFrameBody`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/frame.go#L462) transfers that buffer without another frame-sized copy. |

## Partition-key and token derivation

- [`Query.GetRoutingKey`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/session.go#L2203) calls [`Session.routingKeyInfo`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/session.go#L920), which may prepare on an available connection before host selection. Its cache key is keyspace plus statement. Protocol v4+ prepared metadata supplies partition-key argument indexes; otherwise table metadata supplies the mapping. The result contains indexes, `TypeInfo` entries, actual target keyspace/table, LWT status, and optional custom partitioner.
- [`createRoutingKey`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/session.go#L3686) calls `Marshal` again for partition-key arguments. A single key returns that encoded value. A composite key constructs `[uint16 length][component][0]` sequences, then allocates/copies a final returned key.
- These bytes are independent of the later `queryValues` serialization. Custom marshalers can therefore run for routing and execution separately; mutation or nondeterministic serialization can make them disagree.
- Routing callbacks created with `Session.Bind` generally have no values available at this stage and bypass automatic routing. [`Batch.GetRoutingKey`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/session.go#L3644) uses only its first entry and bypasses callback-bound entries.
- [`tokenAwareHostPolicy.Pick`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/policies.go#L950) consumes the complete key slice and hashes it. [Murmur3](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/token.go#L73) already has a raw-int64 path; [CDC](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/scylla_cdc.go#L41) extracts a raw int64 from the key. That token reaches [`hostConnPool.PickConn`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/connectionpool.go#L344) and [`scyllaConnPicker.pickInt64Locked`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/scylla.go#L522), where tablet placement can override calculated shard placement.
- Routing errors cause fallback policy selection. `createRoutingKey` indexes supplied values without its own bounds validation and narrows composite component lengths to two bytes without a size check. Binding validation currently happens later in connection execution. A new execution preparation boundary should own those checks before routing.

## Response decoding, paging, and buffer release

- [`parseResultRows`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/frame.go#L1223) parses metadata and row count only; row values remain in the framer. [`ReadBytesInternal`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/frame.go#L1997) returns a subslice and advances the framer cursor without copying.
- [`Iter.Scan`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/session.go#L3068) obtains those slices and calls [`scanColumn`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/session.go#L2982), which calls `Unmarshal(TypeInfo, bytes, any)`. Tuple columns are flattened across `[]any` destinations, using `actualColCount` rather than physical column count.
- [`iterScanner.Next`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/session.go#L2942) stores borrowed cell slices in `[][]byte`; its `Scan` still takes `...any`. It therefore avoids a cell-byte copy but is not a typed decoder.
- Built-in text/blob decoding into strings copies; decoding into `[]byte` copies into reusable destination capacity. See [text decoder utilities](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/serialization/text/unmarshal_utils.go) and [blob decoder utilities](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/serialization/blob/unmarshal_utils.go). [`DirectUnmarshal`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/marshal.go#L115) also clones. Custom `UnmarshalCQL` receives borrowed bytes whose documented validity ends when the callback returns.
- Collection decoders allocate reflected containers and recursively invoke `Unmarshal`; UDT struct decoding rebuilds reflection field maps. Dynamic `RowData`/map helpers additionally allocate `[]any`, reflection-created destinations, and defensive slice copies; see [`newScanValues`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/helpers.go#L521) and [`rowMap`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/helpers.go#L419).
- [`Iter.finalize`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/session.go#L2861) releases the current framer and closes prefetched work. [`fetchNextPage`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/session.go#L2897) releases the old page before fetching/transferring the next page. Exhaustion and scan errors finalize too; stopping early requires `Close` or scanner `Err`.
- Paging state, prepared IDs, result metadata IDs, custom payload bytes, and metadata strings are copied during parsing. They can survive framer recycling. Cell slices cannot. The relevant helpers include [`readBytesCopy`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/frame.go#L2013), [`readShortBytesCopy`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/frame.go#L2029), and [`readString`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/frame.go#L1944).
- [`connFramers.releaseRead`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/framer.go#L155) uses an atomic released guard, resets metadata, and returns the framer to a pool. This is single-owner recycling, not a shared page lease: it cannot preserve views held by multiple rows, and its guard is reset when the framer is acquired again.
- Result metadata can change on an execution or page turn. [`executeQueryWithMetrics`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/conn.go#L2786) replaces cached prepared metadata by identity and uses the live response metadata for that result. Any typed decoding plan must bind to the actual metadata generation, including refreshed metadata and the no-metadata reuse path.

## Cancellation and ownership constraints

- [`contextWriter`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/conn.go#L1946) deliberately ignores request cancellation after a write starts. The coalescer waits for its result once queued; the direct writer holds its serialization semaphore until `Write` returns. Borrowed request spans must remain valid until that completion, even after cancellation.
- After a successful write, cancellation/timeouts leave the stream reserved until a response arrives or connection shutdown drains it. [`processFrameSource`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/conn.go#L1188) either transfers the response framer or releases it via `abandonRecvCall`. This separation prevents late responses from matching reused stream IDs.
- Speculative execution returns a winner and cancels sibling work; it does not join every sibling before returning. [`queryExecutor.run`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/query_executor.go#L402) discards loser iterators. Query refcounts keep the query object alive, but [`cloneQuery`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/session.go#L2066) shares arguments, custom payload, page state, routing key, and callback state. Returning a winning result does not inherently prove no sibling still reads caller-owned arguments.
- Paging clones likewise share input values and can execute asynchronously. A request borrowing contract must cover retries, speculative attempts, and future pages, or snapshot serialized input before these branches. See [`cloneQueryForNextPage`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/conn.go#L2883) and [`nextIter`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/session.go#L3217).
- [`prepareStatement`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/conn.go#L2456) intentionally executes shared preparation under the connection context and lets individual waiters cancel. In contrast, cached `routingKeyInfo` waits through `WaitGroup.Wait`, with no caller-context select.
- `executeBatch(ctx, batch)` passes `batch.Context()` to preparation and execution instead of the supplied attempt context. That is a specific seam to correct if a replacement engine expects speculative cancellation to govern every batch attempt.
- Iterator lifecycle uses an atomic closed flag, but cursor/page/framer fields are not comprehensively synchronized. That flag alone should not become a guarantee of concurrent scanning, view access, and close.
- Bounds-error conversion is currently split: [`parseFrame`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/frame.go#L501) recovers malformed-frame panics, but row consumption happens afterward. `ReadBytesInternal` calls panic-based [`readInt`](https://github.com/scylladb/gocql/blob/1ceaac8172bda26e8b8d701ac356982d33729b27/frame.go#L1925); a truncated cell length prefix therefore sits outside that recovery boundary. A typed cell reader should return checked errors for both prefix and payload truncation.

## Internal implementation boundaries for a typed path

These are required implementation seams inferred from the audit, not proposed public API signatures.

1. **Typed value encoding into an owned output sink.** Replace per-value `Marshal → []byte → queryValues → writeBytes` with recursive typed encoders that write lengths and contents directly into execution-owned storage, or explicitly retained payload spans. Keep null, empty, and unset distinct. Scalar specialization alone does not remove nested-container intermediates.

2. **A validated execution input shared by routing and sending.** It needs schema/type validation, bound-value count checks, partition-key component locations, and either canonical encoded spans or a coherent encoding/hash sink. Routing must derive from the same values sent, without invoking dynamic marshalers again.

3. **Late attempt-specific envelope construction.** Prepared IDs are cached per host/keyspace/statement; stream ID, protocol options, result metadata ID, and compression/framing are connection-dependent. Reusable typed value payloads must remain separable from these per-attempt envelope fields.

4. **An explicit transport ownership contract.** The present single-`[]byte` `contextWriter` is the limiting seam for scatter/gather payloads. Removing copies beyond frame assembly requires coordinated changes to request ownership, v5 segment checksums/layout, compression, write completion, and TLS fallback.

5. **A page owner separate from the mutable decode cursor.** Typed decoding can consume checked raw cells directly, with scalar values decoded by value and borrowed text/blob/collection views tied to a page owner. Retained views require ownership beyond today's unconditional page-release behavior; whole-page retention has a meaningful memory cost.

6. **Typed decoding plans keyed to validated metadata.** Bind column/UDT/tuple structure once, bypass `scanColumn`, `Unmarshal`, tuple destination flattening, and map helpers. Revalidate or replace the plan when live response metadata changes.

7. **Execution-level lifetime management.** Input ownership must extend across retry/speculation/paging; response ownership must handle winners, losers, prefetched results, early close, and cancellation exactly once. The current stream lifecycle and framer handoff are useful foundations, but query refcounts are not input-buffer leases and framer pooling is not borrowed-row ownership.
