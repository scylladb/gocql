## Verified findings and fixes

1. **Full-fetch exclusion was stated more strongly than cancellation actually guarantees.** `scylla/src/cluster/metadata/worker.rs:349–435` replaces `PendingFetches` and drops partial-fetch futures. However, `scylla/src/client/pager.rs:1118–1175` fetches the first page in the caller and spawns a separate task for later pages; `fetch_remaining_pages` at `646–690` waits for a page before checking for consumer loss by sending its result. That task retains `Arc<Connection>` (`539–548`). `scylla/src/network/connection.rs:138–176,195–225` marks a dropped request future as orphaned rather than cancelling server execution. Fixed the scheduling paragraph and invariant to distinguish exclusion of scheduler fetches/results from network work that can outlive preemption and overlap the replacement fetch. Added source links and a coverage gap for preemption during later-page work.

2. **Refresh caller cancellation and the event-barrier boundary were unspecified.** `scylla/src/cluster/worker.rs:203–218` enqueues a request before awaiting its separate reply; no cancellation message retracts that request. The metadata worker owns the accepted request (`metadata/worker.rs:73–89,1041–1059`), and publication ignores a dropped reply receiver (`cluster/worker.rs:514–520`). `metadata/worker.rs:831–851` excludes new refresh requests while a full fetch runs, while server events continue adding follow-up work. `metadata/update.rs:113–175` preserves reply senders when newer full metadata replaces pending metadata. Added that caller cancellation after enqueue leaves the fetch owed, that completion does not flush all already-received server events, and that one coalesced publication may answer multiple callers. This preserves the existing after-publication success guarantee.

3. **Pending keyspace absence is not preserved against a later recoverable error.** `SchemaUpdate::merge` (`metadata/update.rs:384–405`) protects only an older `Present(Ok(_))`; `Absent` is replaced by a newer `Present(Err(_))`. Full-result merging (`113–175`) likewise carries forward only valid pending keyspaces, not absence. Applying that error uses `ClusterState::resolve_metadata_keyspace` (`cluster/state.rs:508–533`), which consults the old published keyspace map. Therefore a pending drop followed by an error can reuse pre-drop schema, while publishing the drop first prevents that reuse. Added this timing-dependent limitation rather than implying a durable deletion marker. The existing `absent_then_broken` assertion (`metadata/update.rs:1001,1010,1029–1035`) already proves the merge result; the spec now distinguishes that coverage from the missing coalesced-versus-separate state-application regression.

4. **Safe snapshot retention needed a resource-lifetime and pre-publication mutation qualification.** `ClusterState` retains `Arc<Node>` through its topology (`cluster/state.rs:44–55,95–115`); `Node` owns its pool (`cluster/node.rs:83–99`), and `NodeConnectionPool` retains an `Arc<RemoteHandle<()>>` (`network/connection_pool.rs:191–202`). Removed/replaced nodes are omitted from the new map, with no explicit teardown of pools still held by old readers (`cluster/state.rs:423–488`). An address-only replacement calls `Node::inherit_with_ip_changed`, which updates the shared pool endpoint before returning the replacement node (`cluster/node.rs:175–190`); publication follows state construction later (`cluster/worker.rs:450–514`). Added that retained snapshots keep pools alive, old node addresses can differ from the shared pool's updated endpoint, and removal is not immediate resource closure. The shutdown section now also distinguishes stopping the cluster workers from retained pools, spawned pagers, and already spawned blocking locator work (`cluster/state.rs:569–583`).

5. **Connectivity callbacks have no pool-generation validation.** `ConnectivityChangeEvent` contains only a host ID (`network/connection_pool.rs:1577–1593`), and pools emit it after replacing their connection list (`1233–1301`). The consumer resolves that ID against the current snapshot and status map, uses the current node address, and does not compare pool identity, current enabled state, or actual connectivity (`cluster/worker.rs:760–800`). Retained old pools and queued older events can consequently affect notifications for a replacement node with the same ID. Added this limit to the host-listener contract and a specific missing regression. The existing suppression of repeated equal statuses and ignoring unknown/removed IDs remains correctly documented.

6. **Agreement membership and cancellation boundaries were omitted.** Each check captures one `ClusterState`, obtains working connections, and `join_all`s all per-node reads before examining any result (`client/session.rs:2706–2745`; connection enumeration at `cluster/state.rs:744–786`). Within a node, connections are attempted sequentially (`client/session.rs:2782–2813`). A new invocation captures a fresh snapshot; an in-progress check does not add nodes from a newly published topology. The waiting method wraps the entire loop in `timeout` (`2639–2691`), whereas the public one-shot check delegates without that agreement wrapper (`2694–2699`). Added these boundaries and noted that the result does not freeze subsequent schema changes. Added test gaps for membership replacement during a check and blocked one-shot checks versus the waiting deadline.
